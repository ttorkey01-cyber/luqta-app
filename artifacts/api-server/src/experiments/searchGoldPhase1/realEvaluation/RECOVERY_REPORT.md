# Search Core Recovery — 40-case real-source replay

This is an **experimental, descriptive** evaluation, not shopper-traffic evidence or a production readiness claim. The 40 preregistered cases and judgment definitions were not changed. Their SHA-256 is `4359419400333f3a2831cc30efe65c9be4bea90cf19732b3e4e51dceb6a895f8`. Historical V2/Phase 1B observations and independent labels were carried forward as evidence, not used as the implementation base.

1. **Branch and commit.** `experiment/search-core-recovery` was created from the frozen Phase 1B GitHub commit `b20cb956287485dd57d421fef92935c12e29269b`. The recovery commit is recorded with the branch delivery; GitHub `main` was checked separately and must remain at `8698bcc63819e11794a251fda6661136ee1079a8`.
2. **Files changed.** Only `artifacts/api-server/src/experiments/searchGoldPhase1/` implementation/tests and its `frozenPhase1b/` control plus `realEvaluation/` runner, scoring tools, blinded packets, independent judgments, observations, scorecards, and this report. No production search route or connector implementation changed.
3. **Architecture.** The wrapper calls unchanged V2 first as a discovery floor, then bounded exact/lexical/fallback plans. Candidate lifecycle and evidence statuses distinguish retrieved, normalized, rejected, display-eligible, and ranked results. Unknown hard evidence can remain a labeled discovery candidate but cannot verify a claim; verified conflicts and reliably unavailable offers are rejected. Product/variant/merchant offer grouping is distinct. The parser preserves contextual sizes and treats a referenced model in an explicit alternative search as a retrieval anchor. A conservative identity assertion check and source-backed same-variant comparison gate run on the experimental path only.
4. **Replay and drift.** One diagnostic three-arm replay ran 2026-09-30 09:43–09:46 UTC; its unsupported EXACT assertions prompted a documented experimental fix. The final, unchanged 40-case three-arm replay ran 09:58–10:00 UTC with rotated arm order, shared preflight, and current authorized sources. Neither replay had an observed provider failure. Historical-to-final inventory assessments changed from **unknown to found in cases 8 and 29**; do not compare those cases directly with the historical score. In case 29 the recovery arm's candidate cohort rose from 17 to 117 between the two new runs, including 115 feed contributions in the final run; this is source/index availability drift, not proof of a search improvement. The final scorer marks 17 cases directly comparable to historical evidence; the other 21 without drift lack sufficient historical/final judged-window or inventory evidence.
5. **Historical V2 metrics.** Precision@1 9/14 (64.3%), precision@3 33/42 (78.6%), success@5 14/14 (100%), supported exact rank-1 6/9 (66.7%), irrelevant top-five 6/65 (9.2%), zero results 13/40.
6. **Historical frozen Phase 1B metrics.** Precision@1 9/14 (64.3%), precision@3 26/42 (61.9%), success@5 11/14 (78.6%), supported exact rank-1 5/9 (55.6%), irrelevant top-five 3/50 (6.0%), zero results 24/40. Independently adjudicated false EXACT: 7/14 (50%).
7. **Final recovery metrics.** Precision@1 14/16 (87.5%), precision@3 34/48 (70.8%), success@5 15/16 (93.8%), supported exact rank-1 2/9 (22.2%), irrelevant top-five 6/75 (8.0%), zero results 15/40. **False EXACT remains 6/15 (40%)**, not near zero.

9. **Precision@1.** Recovery's 14/16 exceeds same-run V2's 12/16 and the historical V2 reference of 9/14. This is descriptive, subject to case 8/29 inventory drift.
10. **Success@5.** Recovery equals same-run V2 at 15/16. It does not establish improvement over historical V2's 14/14 because the inventory denominator changed; do not pool 14 and 16.
11. **Supported exact rank-1.** Recovery and same-run V2 are both 2/9; neither reaches historical V2's 6/9. Verified identity/offer evidence, not similar title text, determines this metric.
12. **False-EXACT audit.** Of 15 adequately adjudicated recovery EXACT assertions, six were independently labeled `PROBABLE_EXACT`, not EXACT: four case-1 Samsung S24 pages with insufficient individual-offer evidence and two case-27 Nike style-code pages without a supported individual offer. None were unadjudicated in the final replay. This 40% error rate is only modestly below Phase 1B's 50%; it fails the near-zero safety target. The scorer's legacy `recoveryArmExactAssertionsDowngradedFromExact` field is a deprecated alias for this **unsupported assertion count**, not a firewall effect.
13. **Irrelevant results.** Recovery's 6/75 top-five rate (8.0%) is below the historical V2 9.2% reference and same-run V2's 8/72 (11.1%). This improvement does not cancel the exact-assertion failure.
14. **Zero results.** Recovery 15/40 is materially below Phase 1B 24/40, but above same-run V2 13/40. Cases 23 and 32 are V2-positive and recovery-empty.
15. **Useful V2 candidate retention.** Within the final same-run cohort, 175/178 independently useful V2 candidates remained displayed by Recovery (98.3%); three were lost (two in case 6, one in case 27). The experimental filter suppressed 125 independently labeled irrelevant V2 candidates. Candidate retention does not guarantee top-five rank retention.
16. **Alternatives recovered.** Fifty-nine independently labeled `ALTERNATIVE` candidates appeared in Recovery but not Phase 1B (30 `RELEVANT`, 29 `PARTIALLY_RELEVANT`), in cases 29, 30, and 40. Some case-29 candidates were only partial/unknown-evidence discoveries, not verified cheaper offers or savings.
17. **EXACT downgrades.** Thirteen same-run Phase 1B EXACT IDs remained displayed but were classified below EXACT by Recovery (two in case 1, eleven in case 27). Separately, nine candidate annotations in cases 28–30 record alternative-reference demotion from an initial exact/probable class; these nine are **not** all proven to have been initial EXACT claims. Neither count is the six post-hoc false-EXACT findings.
18. **Arabic and mixed language.** Arabic success@5: historical V2 3/3, Phase 1B 1/3, final V2 4/4, Recovery 4/4. Case 13 (`Nike أسود مقاس EU 42`) now parses **EU 42** explicitly and displays two related discovery candidates instead of Phase 1B's zero; both have **unknown size evidence** and neither is claimed as verified size 42. There is no separately preregistered mixed-language aggregate denominator, so do not invent one.
19. **Hard constraints.** Verified displayed-result compliance is Recovery 248/476 versus same-run V2 135/464; unknown is never a pass in this metric. Strict max price stays hard; approximate Saudi budget stays a preference. Unknown size/color/price can remain visible only with a nonqualifying evidence verdict; verified mismatches are rejected. No cross-currency strict-price satisfaction is inferred.
20. **Identity/variant/offer.** Distinct Nike colorways/styles and unknown variants cannot support EXACT merely through brand/category similarity. Grouped merchant offers retain separate stock, price, condition and freshness; an out-of-stock offer cannot poison a current offer. Nevertheless, the final individual-offer audit above shows this assertion firewall is still insufficient.
21. **Same-product-cheaper safety.** A savings claim still requires two current in-stock, fresh, comparable offers with a source-verified matching checksum-valid GTIN-14, agreeing currency, color and condition. No live case supplied that pair, so the final replay makes **no verified savings claim**. A similar cheaper discovery is labeled separately and does not create an invented reference price; the focused two-offer GTIN test passes.
22. **Every observed regression.** Relative to same-run V2: recovery has two extra zero-result cases (23, 32), three useful candidate losses (case 6 ×2; case 27 ×1), fewer relevant top-five results in cases 2, 5, 27, 40, higher median and p95 latency, and no exact rank-1 gain. Against the historical V2 reference, supported exact rank-1 is substantially lower (2/9 versus 6/9), but cross-run inventory/label drift precludes attributing that difference solely to the algorithm. The two inventory-assessment changes (8, 29) are explicitly excluded from direct historical comparability.
23. **Latency.** Same-run V2 median/p95 788/2689 ms versus Recovery 1085/4553 ms (40 cases each). Recovery made 97 underlying V2 calls across the cases, with 27 Brave requests and 35 Brave cache hits recorded; bounded extra retrieval costs latency. Arm rotation and shared preflight reduced, but did not remove, cache/source-order effects.
24. **Verification.** Focused experiment/scorer tests: **104/104 passing**; full existing API connector tests: **109/109 passing**; API TypeScript typecheck passed; `git diff --check` passed. The frozen-control implementation and case fingerprint were verified before the live runner imported sources. No production-path wiring was added.
25. **Remaining failure categories.** Six unsupported EXACT assertions (individual offer verification), case-23/32 abstention, three useful V2 candidate losses, four cases with worse top-five ordering, case-29 feed availability variability, and higher p95 latency. These are not silently recast as successful results.
26. **Both recall and safety versus V2? No.** Useful recall and precision improved against same-run V2, and irrelevance fell, but unsupported EXACT remains 40%, exact rank-1 is not better, and two V2-positive queries became empty. The preregistered advancement gate is **not met**.
27. **Proceed to the next Gold Standard capability? No.** Keep this experimental branch isolated and request approval for a further targeted search-core iteration/evaluation before any wider adoption. Do not start Phase 2 from this result.

The GitHub `main` branch and production search/backend were not changed. No Phase 2, semantic/vector system, Gemini, new provider, deploy, OTA, APK/EAS build, or billing change was made. **Stop here for approval.**
