# LUQTA Search Acceptance Tests

Status: proposed pre-implementation acceptance specification. This document defines evaluation behavior; it does not describe existing inventory or authorize implementation.

Related scorecard and metric definitions: [SEARCH_SCORECARD.md](./SEARCH_SCORECARD.md).

## Freeze and evidence protocol

Before implementation or evaluation, freeze and version the authorized catalog/offer snapshots, source timestamps, query set, photo files/rights, and independent gold labels. Preserve a reproducible fixture manifest. Each product/offer field used as evidence must retain its source and timestamp. Do not fabricate listings, prices, stock, identity, attributes, locality, or compatibility. Use merchant images only when documented rights expressly permit this evaluation; otherwise use user-licensed photos or no image. Image gold labels must be independently annotated from the authorized image and corroborating source data, not assumed from a prompt.

Fixtures below use symbolic labels (for example, `E1`, `F_color`) rather than asserting that any real product or offer exists. Populate them only from the frozen authorized data. If required evidence is absent or conflicting, the correct result is uncertainty, clarification, or abstention—not an invented fact. Strict constraints are exact filters unless the query expressly uses soft language such as “around/about.” “Exact” means identity supported by a stable identifier or adequate source-backed brand/model identity; “close” means a relevant but non-identical product and must be labeled as such.

For every row, **PASS** means the full expected behavior is met using the named fixture evidence and no unsupported assertion is made. **FAIL** means any required behavior is missed, a hard constraint is relaxed, an irrelevant result is presented as relevant, or an unsupported fact is stated.
